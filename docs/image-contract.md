# 配图交接协议

本协议连接写作规则与独立图片能力。写作 Skill 负责说明要什么图和如何验收；项目流程负责提交需求、取得图片、交回验收。图片能力不修改正文，也不决定是否需要配图。

## 配图需求：image-requests.json

文件放在当前文章目录。三种写作视角共用格式，不包含后端、模型、API、凭证或服务地址。

```json
{
  "version": 1,
  "images": [
    {
      "id": "cover",
      "role": "cover",
      "output": "cover.png",
      "width": 1024,
      "height": 432,
      "type": "concept",
      "style": "简约科技插画",
      "palette": ["#1a1f5c", "#7c3aed", "#ffffff"],
      "composition": "左侧标题，右侧用知识卡片与光线表达检索；留白充足",
      "text": ["让 AI 找对资料"],
      "prompt": "用连接知识卡片的光线表达检索增强，主题明确，避免无关机器人",
      "placement": "cover-only",
      "alt": "文章封面",
      "acceptance": ["标题清晰可读", "主题与正文一致", "画面只保留一个焦点"]
    }
  ]
}
```

每篇完整文章固定一项封面需求。正文配图按需追加 `role: content` 项，也可以没有；结构图是可选正文配图。正文配图的 `placement` 应完整且唯一地匹配 `draft.md` 中的标题行或段落文本，程序在该位置之后插入图片，`alt` 应说明图的内容。

- `id`：唯一标识，仅字母、数字、下划线和连字符。
- `output`：文章同目录内唯一的 PNG 文件名，不带路径；封面固定为 `cover.png`。
- `width`、`height`：目标像素尺寸。写作约定为封面 1024×432，正文配图 1024×768。
- `prompt`：图片内容与表达目的。可以是自然语言设计说明，不是后端调用参数。
- `type`、`style`、`palette`、`composition`：画面类型、风格、配色及构图思路。
- `text`：画面需要出现的原文列表；无文字时用空列表。
- `acceptance`：可检查的设计与内容要求；数据图必须与正文的真实数据一致。

执行器校验标识、文件名、尺寸和字段格式。配图的主题、色调、构图、文字、数据与插入位置由写作侧补全并验收，不由执行器猜测。

## 图片结果：image-results.json

图片能力取得、解码并检查实际图片后，返回结果，例如：

```json
{
  "version": 1,
  "images": [
    {
      "id": "cover",
      "output": "cover.png",
      "backend": "file",
      "width": 1024,
      "height": 432,
      "request_hash": "实际需求内容的 SHA-256",
      "status": "ready",
      "review": "pending",
      "fit": "exact"
    }
  ]
}
```

`ready` 只表示实际文件已取得且通过格式与尺寸校验，**不代表视觉验收通过**。写作侧仍需查看图片，核对文字、事实、色调、构图和正文相关性；实际查看图片后，通过项目工作流的 `complete --reviewed --note` 提交验收，控制器将图片及需求指纹与该阶段验收关联；细节也可补充到 `brief.md`。

需求发生变化后，之前的验收不再自动有效。项目流程需对照需求指纹及实际文件重新检查、取得或验收图片。不要仅凭文件名或旧的 `ready` 状态认定当前需求已完成。

## 七步流程中的交接

固定顺序不变：**搜索资料 → 分析资料 → 写正文 → 生成封面 → 按需生成正文配图 → 生成 Markdown → 排版并保存可发布产物**。

第 4 步由写作侧提交封面需求，项目流程调用独立图片能力，写作侧验收返回图片。第 5 步对每张必要正文配图执行同样交接。第 6 步运行 `workflow finalize`，由程序把 `draft.md` 与实际存在且验收通过的正文图片整合为 `article.md`，封面始终单独处理。第 7 步 `format` 生成 `article.html` 并检查本地图片是否齐备，把图片指纹写入 `publish-manifest.json`。

缺少可用图片来源或验收未通过时，记录未完成事项，不把需求文件当作已生成的图片，也不声称整篇文章已完整交付。

阶段推进与返工规则见 [七步工作流](workflow.md)。
