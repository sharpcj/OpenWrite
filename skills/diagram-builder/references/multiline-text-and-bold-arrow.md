# 多行文字重叠与短距箭头选择规范

> 用途：杜绝两类高频返工——① 一个节点框内多行文字挤在一起 / 溢出；② 并排步骤间的细线箭头缩放后看不见箭杆。
> 来源：2026-11-17「大模型网关技术调研」出图被截图打回两次后固化的实战经验。
> 与 `text-fit-and-centering.md` 的分工：那篇讲「整块文字是否落在框内、是否居中」，本篇讲「框内多行之间、以及框与框之间的连接」——两者互补，出图前后都要过。

---

## 一、多行文字必须单点定位，禁止两处各算一次

### 症状

一个框里要放「标题 / 副标 / 说明」三行，渲染出来第二、三行糊在一起，或说明横穿出框。

### 根因（本次真实事故）

代码里 `box()` 画两行（基线 `y+19` / `y+37`），外面又手动 `append` 一个 `<text>` 补第三行（`y+46`）。第二、三行只差 9px，字号却是 11px —— **多行文字由两处代码分别算坐标，必然算串**。同类变体：`box()` 里塞的是把两行 `replace("\n"," ")` 拼成的一整行，窄框放不下直接溢出，后面补的那行又重复一遍。

### 正确写法：单 `<text>` + `<tspan dy>` 相对定位

```svg
<rect x="26" y="92" width="188" height="72" rx="8" fill="#E6F1FB" stroke="#378ADD"/>
<text x="120" y="111" text-anchor="middle">
  <tspan x="120" dy="0"  font-size="12.5" font-weight="500" fill="#042C53">接入层</tspan>
  <tspan x="120" dy="19" font-size="10"   fill="#042C53">OpenAPI / K8s Ingress</tspan>
  <tspan x="120" dy="16" font-size="9.5"  fill="#666">统一端点，沿用既有网关入口</tspan>
</text>
```

规则：
- 三行基线落在 `y+19 / y+38 / y+55`；行距（dy）19 / 16px。
- 每个 `<tspan>` **必须带 `x`**（与父 `<text>` 相同），否则换行后丢失居中。
- 框高按行数取：1 行 ≥40px，2 行 ≥56px，3 行 ≥72px，底部留 ≥10px 余量。
- 标题变长放不下时优先**降字号**（12.5→10.5），不要改框宽——改框宽会连带所有同排节点的 `cx` 和箭头终点，牵一发动全身。

### 行距底线（硬指标）

相邻两行基线差 ≥ **较大字号 × 1.15**，否则字会贴在一起或相交。

| 字号 | 最小行距（×1.15） |
|------|------------------|
| 12.5 / 10 | 14.4px（取 16~19 稳妥） |
| 11 / 9.5 | 12.7px |
| 10 / 8.5 | 11.5px |

## 二、短距离并排步骤用实心粗箭头，不用细线 + marker

### 症状

五步流程、横向步骤条这类图，节点间距只有 20~30px。用 `<line>` + 小 marker 画箭头，缩放或截图后**箭杆细到几乎看不见**，只剩一个个孤立的小三角。

### 判断标准

| 节点间隙 | 箭头画法 |
|---------|---------|
| < 40px（并排步骤条） | **实心粗箭头 `<polygon>`** |
| ≥ 40px（跨层/长连线） | `<line class="arr">` + marker |

### 实心粗箭头画法

```svg
<!-- 从 x1 到 x2 的实心粗箭头，中心 y -->
<polygon points="131,89.5 144,89.5 144,86 153,92 144,98 144,94.5 131,94.5" fill="#888780"/>
```

尺寸：箭杆半高 2.5px、箭头长 9px、箭头半高 6px。

**关键：用 `<polygon>` 不要用 `<path>`。** 自动校验器的 marker 方向启发式只扫描 `<path d=...>`，用 polygon 不会误触发"箭头方向错误"的告警。

**留白**：框间隙要 ≥24px（本次：中心间距 132 − 框宽 104 = 28px）。间隙太小，箭头头部（9px）会占满，箭杆还是看不见。

---

## 三、元教训：结构校验通过 ≠ 图能用

本次最值得记住的一条：旧的 `validate-svg.py` 只查结构（marker 尺寸、颜色 token、viewBox 高度），一路报「零错误零警告」，但图实际上文字重叠、溢出、箭头看不见。**只查结构的校验器会给虚假的安全感。**

纪律：

1. 出图后必须跑 `scripts/check_svg_text.py`，它查的是**渲染后果**——文字出框、未居中、越界、以及（本次新增）**同一 x 列相邻文字行的基线重叠**。
2. 结构校验（marker/颜色）只是第一关，不能替代文字/箭头的可读性检查。
3. 当前模型看不了图时，用「坐标计算 + 校验器」代替肉眼：先按字号估算文字宽度是否与框宽匹配（`text-fit-and-centering.md` 的 `text_w()`），再确认行距、箭头留白。不要因为校验器说 OK 就交付。

## 四、出图前补充自查清单（叠加在 text-fit 的 5 条之上）

- [ ] 每个框内多行文字来自**单个 `<text>`**，用 `<tspan dy>` 排布，没有手动 append 的第二/第三个 `<text>` 补行；
- [ ] 相邻行基线差 ≥ 较大字号 × 1.15；
- [ ] 框高够（3 行 ≥72px），标题变长时缩了字号而非硬撑；
- [ ] 并排步骤（间隙 <40px）用的是实心 polygon 粗箭头，框间隙 ≥24px；
- [ ] 跑 `check_svg_text.py`，输出「问题 0 处」（含行间重叠检测）。
