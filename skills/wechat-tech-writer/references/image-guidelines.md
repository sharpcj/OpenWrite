# 真实图片的选择与验收规则

本指南只约束图片应表达什么以及是否适合文章；获取、下载、截图、格式转换等操作由项目的独立图片能力负责。

## 适用场景

- 讲解产品实际界面或操作效果时，需求应明确要求真实界面，不把虚构画面当作实际截图。
- 讲解技术原理时，架构图和流程图应与正文中的组件、步骤及连接关系一致。
- 对比数据时，图表必须来自已核实的数据；标签、单位、样本条件和对比维度应明确。
- 概念插画应帮助解释抽象内容，不暗示未经证实的产品功能或事实。

## 选择标准

优先选择能展示正文关键功能、结构或结果的画面。截图需要界面清晰、文字可读、关键信息突出；必要时在设计要求中指定应保留的界面区域。

不使用无关装饰图、模糊图片、密集到无法阅读的架构图、未说明的伪造截图、来源不明或不适合本次使用的素材。图片数量按正文的解释价值决定，每个 H2 最多一张，可以没有正文配图。

## 写入需求

在 `image-requests.json` 中说明：

- 对应的正文段落与解释目的。
- 必须呈现的实际界面、组件、步骤、数据或效果。
- 目标尺寸、色调、构图、文字、图注及验收标准。
- 若资料中已有合适的参考图片，可记录其出处及用途作为设计依据，不直接把远程 URL 当作已交付文件。

写作 Skill 不决定图片由哪个工具或服务取得。

## 返回图片的验收

- 主题、实际界面或图示关系与正文一致。
- 真实截图与示意插画的身份清楚，不混淆事实与表达。
- 文字、数字和数据来源准确，画面重点突出。
- 尺寸符合需求；适配后没有裁掉关键内容或文字。
- 本地文件已实际取得；在正文中引用同目录的图片文件。

通过后才在最终 Markdown 插入图片；没有取得或没有通过验收的图片记录为待办，不使用占位符假装完成，不在正文末尾另加“图片下载列表”。封面始终单独处理，不嵌入正文。
