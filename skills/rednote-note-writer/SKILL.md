# OpenWrite · 小红书图文写作

本技能适用于已确定为小红书平台的任务。平台与视角以任务状态为准，不根据主题词自行切换。遵循 [七步工作流](../../docs/workflow.md)、[配图交接协议](../../docs/image-contract.md) 与 [平台适配器契约](../../docs/platforms.md)。

**产物形态与公众号根本不同**：不是长文，而是「标题 + 短文案 + 话题 + 3:4 组图」。卡片就是内容本体，文案只是笔记说明。

## 写作原则

- 一篇笔记只解决一个具体问题，读完能带走一个可执行结论。
- 标题 ≤20 字，用「情绪词 + 具体对象」或明确利益点，不做无依据的夸大承诺。
- 正文短、口语化、分段清晰；不堆术语，不写公众号式长论述。
- 第一人称经历须来自用户提供的真实经历；没有就用观察或公开案例，不编造「我亲测」。
- 事实与数据须有来源支撑；涉及测评结论要能被卡片内容印证。
- 话题选与内容真实相关的词，不堆无关热词。

## 固定七步

### 步骤 1：搜索资料

保存 `sources.json`：来源、链接与实际提取内容。可把同类爆款笔记的结构拆解作为来源，但不得照搬他人文案。用户提供资料可声明 `kind: user`。

### 步骤 2：分析资料

保存 `analysis.md`，用 `source:<id>` 关联来源。除事实与争议外，额外分析：读者痛点、可用的钩子角度、哪些信息适合做成卡片、哪些必须留在文案里。

### 步骤 3：写正文（先过标题与大纲检查点）

除非任务已授权跳过，必须先取得用户确认：

- 给出**三个备选标题**，均 ≤20 字，风格标注至少包含 `激进悬念` 与 `客观中性`，第三个默认 `利益实用`。小红书语感偏「情绪词 + 具体对象」，但仍要准确、可兑现。
- 同时给出**卡片分页大纲**（每页一个观点）与笔记文案主线，请用户选定标题（可自定义）并确认。
- 用户可反复提修改意见，每轮更新 `outline.md`，确认前不生成全文；确认结果写入 `outline.json`。

确认后产出两份文件：

**`draft.md`（笔记文案）**

```markdown
# 3 个设置让 AI 答得更准

之前问它专业问题，三次答案都不一样。后来改了三个设置，稳定多了。

先开启检索，再限定来源范围，最后要求它给出引用。第三步最容易被忽略，但效果最明显。

话题：AI工具 检索增强 效率
```

- H1 必须与已确认标题一致。
- 正文是短文案，不嵌图片。
- 可选末尾一行 `话题：词1 词2 词3`（用空格、逗号或顿号分隔，不带 `#`）。

**`cards.md`（分页卡片稿）**

```markdown
# 卡片稿

## 第 1 张（封面）
标题：3 个设置让 AI 答得更准
副标题：检索增强的最小可用配置
要点：开启检索 / 限定来源 / 要求引用

---

## 第 2 张
标题：为什么它会答错
要点：
- 模型知识有截止时间
- 缺少你的私有资料
- 没有引用约束

---

## 第 3 张
标题：三步怎么配
要点：
- 开启检索开关
- 指定可信来源
- 要求附引用
```

- **一页一个观点**；页标题尽量 12–30 字，配 2–4 条短片段或一段简洁文字。
- 张数**由内容动态决定**，不为凑数加页，也不把多个观点挤进一页。
- 卡片稿是渲染输入：改卡片文案必须重渲对应卡片（`cards.md` 已纳入第三步指纹）。

提交 `--step draft`。

### 步骤 4：生成封面（即组图首图）

封面不是独立于正文的图，而是**第 1 张卡片**，须与后续卡片视觉统一。

在 `image-requests.json` 写入封面需求：

```json
{
  "id": "cover", "role": "cover", "output": "xhs-01-cover.png",
  "width": 1080, "height": 1440,
  "prompt": "封面：突出三个设置带来的确定性",
  "card": {
    "layout": "cover", "theme": "indigo",
    "title": "3 个设置让 AI 答得更准",
    "subtitle": "检索增强的最小可用配置",
    "bullets": ["开启检索", "限定来源", "要求引用"],
    "footer": "OpenWrite 实测"
  },
  "acceptance": ["标题与已确认标题一致", "文字无错漏", "版式不溢出安全区"]
}
```

项目流程用 `--backend html` 渲染，取得图片后按设计要求验收，提交 `--step cover --reviewed --note "验收说明"`。

### 步骤 5：按需生成正文卡片（必需，张数动态）

每张内容卡片一项需求，`role: content`，`output` 用 `xhs-02-<topic>.png` 这类有含义的名字，`width/height` 为 1080×1440，并带 **`order`（从 2 开始的整数，不可重复）** 决定上传顺序。

`card.layout` 可选 `cover` / `bullets` / `quote`；`card.theme` 可选 `default` / `indigo` / `forest` / `kraft` / `midnight`，整套保持一致。

保存 `content-images.json`：`needed: true` 并说明为什么需要这些卡片。逐项渲染、逐张验收后提交 `--step content --reviewed --note "验收说明"`。

**验收要点**：文字与卡片稿一字不差、无错字漏字、版式不溢出、字号可读、留白合理、与文案结论一致、数据真实。渲染器会做溢出与字号校验，但**内容正确性仍须实际看图确认**。

### 步骤 6：生成 Markdown

由项目控制器运行 `workflow finalize`，整合生成 `note.md`（标题 + 文案 + 话题）。**不嵌入卡片图片**——卡片顺序由发布清单表达。

### 步骤 7：生成可发布交付件

运行 `python3 openwrite.py format <目录>`。小红书第七步**不做渲染**（卡片已在第 4/5 步完成），只组装卡片顺序、校验可发布性（标题长度、每张尺寸与格式、张数与顺序、文案完整性）并写入 `publish-manifest.json`。

七步完成即交付可发布产物。用户明确要求发布时，项目入口调用 `rednote-publisher`：默认「仅自己可见」，公开需显式 `--public` 授权，可先 `--dry-run` 预演。只有观察到站点成功信号才报告已发布；未发布或失败时如实说明，不声称已发布到小红书。

## 边界

- 不代替用户切换到微信平台，也不套用微信写作 Skill 的长文规则。
- 正文长度与单篇图片上限以 `platforms.py` 的当前 `limits` 为准，由代码检查；超限时调整内容或分页，不静默截断。平台规则如有变化，应核实后同步注册表与文档。
- 缺少渲染依赖（playwright / Chromium）时说明缺口并保留卡片稿与需求，不伪造图片。
